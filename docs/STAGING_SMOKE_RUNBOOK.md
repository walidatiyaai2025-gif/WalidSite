# T025 — Read-only staging smoke gate (#26)

After an immutable release is built, its integrity checked and its Laravel database migrated on an **authorized public HTTPS staging host**, run:

```bash
python3 -B qa/staging_smoke.py --url https://staging.your-public-domain.com \
  --approved-host staging.your-public-domain.com \
  --output /secure/evidence/walidsite-staging-smoke.json
```

The runner accepts **no credentials**, does not weaken TLS validation, does not follow redirects, and issues **28 GET-only checks**, including 17 private-file/directory denial probes. The checks cover Laravel `/up`, public home, Admin login, locked `/setup` and `/install`, guest `/admin/updates` redirecting **only** to same-origin `/admin/login`, public bootstrap/home/projects JSON, denied guest mobile/admin APIs, and denial of `.env` variants, SQLite/config/cache/log/setup-token files, Git/vendor/contracts, and private release/maintenance/writer-lock/release/backup paths. The exact list is the `CHECKS` tuple in `qa/staging_smoke.py`; this runbook does not duplicate that source of truth.

The required `--approved-host` must exactly match the URL hostname. The runner resolves the approved hostname for each HTTPS request, rejects the request if **any** returned A/AAAA address is not globally routable, pins the selected numeric public IP for that connection, and retains the original hostname for TLS certificate validation and SNI. It rejects IP-literal targets, non-public DNS suffixes, embedded credentials, arbitrary paths and query strings, cross-origin redirects and proxy tunnels. This prevents DNS rebinding between the per-request DNS check and TCP connect. It is still **not proof of network-wide egress isolation**: run only from an operator-managed, egress-restricted environment that blocks RFC1918, loopback, link-local, metadata services and other unauthorized destinations. Independently verify firewall/proxy policy; the runner reports `network_egress_isolation_verified=false` and does not attest the surrounding network controls.

A receipt contains observed HTTP statuses and generic error codes only, never response bodies, credentials, PII or tokens. Exit **0** means all 28 HTTP checks passed, **1** means a failed check, and **2** means invalid input or report write failure. Unexpected redirects (including an external guest Admin Updates login redirect), TLS/DNS errors, exposed setup or private files, an accidentally public private API, malformed/ambiguous/non-finite JSON, slow responses and 5xx are failures. The single allowed redirect is an unauthenticated `/admin/updates` response of HTTP 302 to the exact same-origin owner login; the checker never follows it. Existing receipt files are never overwritten. Archive the receipt privately with the external deployment change ticket, checked artifact SHA, environment record and installation time.

**No deployment or release readiness is certified by this tool.** It cannot verify the installed commit SHA, actual DB backup/restore, migrations, queue workers, mail delivery, AI services, screen pixel fidelity, Flutter devices, rollback or owner acceptance. The output always says `network_egress_isolation_verified=false`, `production_ready=false` and `deployment_release_sha_verified=false`, `backup_restore_verified=false`, `rollback_verified=false`. Each still requires separate, independently witnessed real staging evidence, T024/G-01..G-20 acceptance, and T026/T027 release/owner gates. Keep Issue #26 open until those pass.

Repository CI runs only the **synthetic, offline** `qa.tests.test_staging_smoke` regression tests; it never accesses a staging host. No third workflow is introduced. A complete rehearsal must deploy a versioned artifact, inspect migration state, take and restore a verified private backup on an isolated instance, run authenticated functional/security checks, verify mail/AI truthfully, execute this read-only smoke check, and conduct a timed rollback to a tested previous release without data loss.
